# Recap — 恢复项目上下文

## 触发场景

- 新对话开始，需要快速恢复上下文
- 离开项目一段时间后回来
- 需要了解项目当前整体状态
- 用户说「继续上次的工作」「上次做到哪了」等

## 执行步骤

### 第 1 步：读取当前状态快照

读取 `docs-harness/progress.md`，了解：

- 当前进行中的工作
- 待办事项
- 卡点和待决策事项
- 近期决策记录

### 第 2 步：读取最近工作日志

读取 `docs-harness/memory/` 目录下最近 3 天的日志文件（按文件名日期排序，取最新的 3 个）。

如果 memory 目录为空或没有日志文件，跳过此步骤。

### 第 3 步：读取进行中需求的详情

根据 progress.md 中列出的「当前进行中」的需求：

1. 读取 `docs-harness/requirements/README.md` 获取需求索引
2. 读取对应需求的 `task-items.md` 了解具体任务进度
3. 如需要，读取 `solution.md` 了解实现方案

### 第 4 步：输出上下文摘要

以结构化格式输出上下文摘要：

```
## 项目上下文恢复

### 当前状态
[从 progress.md 提取的当前进行中工作和状态]

### 最近工作回顾
[从最近工作日志中提取的关键信息：完成了什么、做了什么决策、遇到了什么问题]

### 进行中需求详情
[从 task-items.md 提取的具体任务进度]

### 卡点和待决策
[未解决的问题和待决策事项]

### 建议下一步
[基于以上信息，建议接下来做什么]
```

## 注意事项

- recap 是只读操作，不修改任何文件
- 如果 docs-harness/ 下没有任何工作记录（项目刚初始化），说明这是全新开始，引导用户描述当前要做的工作
- 输出应简洁有重点，不要把日志全部复制粘贴，而是提炼关键信息
- 如果日志中有明确的「下一步」指示，优先展示
